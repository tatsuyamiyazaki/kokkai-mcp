# 追加する機能の統合仕様

## 1. 論点別要約機能

### 目的

会議や発言群を、単一の総合要約ではなく、**複数の論点単位に分けて要約**する。

### 役割

* 議論のテーマを2〜5件程度に分解する
* 各論点に属する発言群をまとめる
* 各論点ごとに要点と出典を返す

### 出力イメージ

```json
{
  "topics": [
    {
      "topic": "生成AI活用の推進",
      "summary": "政府や企業における活用促進の必要性が議論された。",
      "sources": []
    },
    {
      "topic": "生成AI規制と安全性",
      "summary": "誤情報や権利侵害への懸念から一定のルール整備が求められた。",
      "sources": []
    }
  ]
}
```

### 実装ポイント

* 最初にLLMで論点候補を抽出
* 各発言を論点に分類
* 分類不能な発言は「その他」に退避
* 論点数は多くしすぎない

---

## 2. 発言者比較機能

### 目的

同じテーマに対して、**誰がどういう立場を取っているか**を比較できるようにする。

### 役割

* 発言者単位で主張をまとめる
* 論点ごとに発言者の差を出す
* 立場差があれば明示する

### 出力イメージ

```json
{
  "speaker_comparison": [
    {
      "speaker": "A議員",
      "position": "規制強化寄り",
      "point": "生成AIのリスクを重視し、制度整備を優先すべきと主張。",
      "sources": []
    },
    {
      "speaker": "B大臣",
      "position": "活用推進寄り",
      "point": "産業競争力の観点から活用促進を進めるべきと説明。",
      "sources": []
    }
  ]
}
```

### 実装ポイント

* speaker単位で発言をまとめる
* 各speakerの要旨を作る
* 立場ラベルは固定候補から選ばせると安定する
  例:

  * 推進
  * 慎重
  * 規制強化
  * 中立
  * 説明中心

---

## 3. 出力テンプレート強化

### 目的

返却形式を統一し、**読みやすく、資料転記しやすい形**にする。

### 推奨テンプレート

```text
■ 会議概要

■ 論点別整理
- 論点1
- 論点2
- 論点3

■ 発言者別比較
- 発言者A
- 発言者B
- 発言者C

■ 結論

■ 出典
```

### JSON出力例

```json
{
  "overview": "...",
  "topics": [
    {
      "topic": "...",
      "summary": "...",
      "sources": []
    }
  ],
  "speaker_comparison": [
    {
      "speaker": "...",
      "position": "...",
      "point": "...",
      "sources": []
    }
  ],
  "conclusion": {
    "text": "...",
    "sources": []
  }
}
```

# 追加後のツール仕様変更案

今の `summarize_speeches` と `summarize_meeting` を拡張するのが自然です。

## 入力パラメータ追加案

```json
{
  "mode": "standard",
  "focus": "生成AI",
  "include_topics": true,
  "include_speaker_comparison": true,
  "output_template": "analysis"
}
```

### 追加パラメータ

* `include_topics`: 論点別整理を含めるか
* `include_speaker_comparison`: 発言者比較を含めるか
* `output_template`: 出力形式

  * `standard`
  * `analysis`
  * `brief_report`

### おすすめ既定値

* `include_topics = true`
* `include_speaker_comparison = true`
* `output_template = analysis`

これで、新しい拡張機能を標準動作にできます。

# 内部処理の分割案

実装は次のモジュールで分けるときれいです。

## `topicExtractor.ts`

役割:

* 論点抽出
* 発言→論点マッピング

## `speakerComparator.ts`

役割:

* 発言者ごとの主張整理
* 立場差抽出

## `summaryFormatter.ts`

役割:

* テンプレート整形
* JSON出力整形
* markdown出力整形

今の `summarizer.ts` に全部押し込むより、この3つに分けた方が後で楽です。

# 出典の付け方

この3機能をまとめて追加する場合、出典の粒度はこう揃えるのがおすすめです。

## 論点別整理

* 各論点に 1〜3件

## 発言者比較

* 各発言者に 1〜2件

## 結論

* 全体を支える代表出典を 1〜3件

これ以上増やすと読みにくくなります。
証拠は大事ですが、証拠だらけの要約はもう要約ではありません。

---

# 実装順序

まとめて追加すると言っても、内部ではこの順で入れるのが安全です。

## Step 1

出力テンプレートを先に固定する
→ 返す器を決める

## Step 2

論点抽出を追加する
→ 中身の骨組みを作る

## Step 3

発言者比較を追加する
→ 比較軸を足す

## Step 4

出典付与を各セクションに拡張する
→ 信頼性を整える

この順なら、途中で壊れにくいです。

# 追加後の完成イメージ

最終的には、たとえばこんな返し方ができます。

```text
■ 会議概要
生成AIの活用促進と安全性確保の両立について議論が行われた。

■ 論点別整理
1. 生成AIの産業活用
   - 活用推進の必要性が示された
2. 安全性と規制
   - 誤情報や著作権面の懸念が示された

■ 発言者別比較
- A議員: 規制強化を優先
- B大臣: 活用推進とルール整備の両立を説明
- C議員: 教育現場での影響を懸念

■ 結論
全面規制ではなく、活用推進を前提に一定のルール整備を進める方向性が中心だった。

■ 出典
- A議員 / 予算委員会 / 2026-02-10 / speechID: ...
- B大臣 / 予算委員会 / 2026-02-10 / speechID: ...
```

この形まで行くと、かなり実務で強いです。

# 優先判断

「3つまとめて入れたい」は正しいです。
理由は、個別追加よりも**出力モデルを一度で整えられる**からです。

特におすすめなのは、これを**新モードとして実装**するやり方です。

例:

* 従来: `mode=standard`
* 新規: `mode=analysis`

`analysis` では、

* 論点別整理あり
* 発言者比較あり
* 強化テンプレートあり
* 出典あり

と定義してしまうと、運用も説明もしやすいです。
