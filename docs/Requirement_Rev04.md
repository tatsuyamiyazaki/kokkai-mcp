# 1. 質問・答弁ペア要約機能 仕様書

## 1.1 文書情報

* 機能名: 質問・答弁ペア要約機能
* 対象システム: 国会議事録検索・要約MCP
* 版数: 1.0
* 作成日: 2026年4月9日
* 目的: 国会審議における質問と答弁の対応関係を整理し、短時間で論点把握できるようにする

---

## 1.2 背景

国会議事録では、議員の質問と政府側の答弁が連続して記録されるが、発言量が多く、質問と答弁の対応関係が分かりにくい場合がある。
単純な要約では、何に対してどう答えたのかがぼやけやすい。

そのため、本機能では、**質問発言と対応する答弁発言をペアとして整理**し、
利用者が「問い」と「答え」を対で把握できるようにする。

---

## 1.3 目的

本機能の目的は以下の通り。

1. 質問と答弁の対応関係を明示する
2. 論点ごとの問いと回答を短く整理する
3. 回答の明確性や論点ずれを把握しやすくする
4. 出典付きで確認できるようにする

---

## 1.4 対象範囲

### 対象

* 会議録内の質問発言抽出
* 対応答弁の抽出
* 質問・答弁のペアリング
* ペアごとの要約
* 出典付与

### 対象外

* 完全自動の厳密な議事進行解析
* 複数会議をまたいだ質問・答弁追跡
* 発言の政治的評価
* 答弁の真偽判定

---

## 1.5 機能概要

会議録または発言群を対象に、質問発言とその後続の答弁発言を対応づけ、ペア単位で要約する。

### 基本処理フロー

```text
会議録取得
  ↓
発言者属性判定
  ↓
質問候補抽出
  ↓
後続答弁候補抽出
  ↓
質問・答弁ペアリング
  ↓
ペア単位要約
  ↓
出典付与
```

---

## 1.6 提供方法

既存MCPに新ツールとして追加する。

### ツール名

* `summarize_qa_pairs`

必要に応じて、既存の `get_meeting` および `summarize_meeting` の内部ロジックを再利用する。

---

## 1.7 summarize_qa_pairs ツール仕様

### 入力例

```json
{
  "issueID": "xyz123",
  "focus": "生成AI",
  "mode": "standard",
  "max_pairs": 10,
  "include_unanswered": true
}
```

### 入力項目

* `issueID`: 対象会議録識別子
* `focus`: 対象テーマ
* `mode`: 出力粒度
* `max_pairs`: 返却する最大ペア数
* `include_unanswered`: 明確な答弁が取れない質問も含めるか

---

## 1.8 出力仕様

### 出力例

```json
{
  "issueID": "xyz123",
  "overview": "生成AIに関する質疑では、安全性、著作権、行政活用が主な論点となった。",
  "qa_pairs": [
    {
      "topic": "生成AIの安全性",
      "question": {
        "speaker": "○○議員",
        "summary": "生成AIによる誤情報拡散への対応方針を質問。",
        "sources": []
      },
      "answer": {
        "speaker": "△△大臣",
        "summary": "関係省庁と連携しつつ、ガイドライン整備を進める考えを示した。",
        "sources": []
      },
      "assessment": {
        "response_type": "direct",
        "note": "質問に対して概ね直接回答している。"
      }
    }
  ],
  "conclusion": {
    "text": "政府側は活用推進を前提としつつ、安全性や権利保護への対応を段階的に進める姿勢を示した。",
    "sources": []
  }
}
```

---

## 1.9 response_type 定義

質問への答弁の関係を以下で分類する。

* `direct`: 質問に概ね直接回答している
* `partial`: 一部回答しているが論点が十分ではない
* `indirect`: 関連説明はあるが、質問に正面から答えていない
* `unclear`: 判定困難
* `unanswered`: 明確な答弁が確認できない

---

## 1.10 処理要件

### 質問候補抽出

以下を手がかりに質問発言を判定する。

* 議員、委員、参考人等の発言
* 疑問表現や確認要求
* 政策説明要求
* 「伺います」「お尋ねします」等の定型

### 答弁候補抽出

以下を手がかりに答弁発言を判定する。

* 大臣、副大臣、政務官、政府参考人等の発言
* 質問直後または近接位置の発言
* 同一論点への応答と推定できる発言

### ペアリング

* 原則として質問直後の政府側発言群を答弁候補とする
* 複数の答弁が続く場合は、同一ペアに束ねる
* 明らかに別論点へ移行した場合は区切る

---

## 1.11 出典付与要件

### 出典対象

* question.summary
* answer.summary
* conclusion

### 出典情報

* speechID
* issueID
* speaker
* date
* nameOfMeeting
* excerpt

### 出典数

* question: 1〜2件
* answer: 1〜3件
* conclusion: 1〜3件

---

## 1.12 モード別仕様

### brief

* 主要な質疑を3〜5件程度
* 各ペアを短く要約
* assessmentは簡易表示

### standard

* 主要質疑を5〜10件程度
* topic、question、answer、assessmentを返す

### detailed

* 主要質疑を詳しく返す
* 必要に応じて論点ごとの複数答弁も含める
* 出典数を増やす

---

## 1.13 受入条件

1. 質問と答弁がペアとして整理されること
2. 各ペアに論点が付与されること
3. 回答関係が response_type で表現されること
4. 出典付きで追跡可能であること
5. brief / standard / detailed の差が反映されること

---

# 2. 政党別比較機能 仕様書

## 2.1 文書情報

* 機能名: 政党別比較機能
* 対象システム: 国会議事録検索・要約MCP
* 版数: 1.0
* 作成日: 2026年4月9日
* 目的: 同一テーマについて、政党ごとの主張や論点の違いを比較できるようにする

---

## 2.2 背景

発言者比較機能では個人単位の違いを見られるが、実務上は政党単位での傾向把握も重要である。
特に、与党・野党、各党の政策スタンス、論点の重視点の違いを把握できると、審議の構造理解が容易になる。

そのため、本機能では、**発言を政党単位で束ねて比較**する。

---

## 2.3 目的

1. テーマごとの政党別スタンスを整理する
2. 重視論点の違いを比較する
3. 共通点と対立点を明確化する
4. 出典付きで比較結果を返す

---

## 2.4 対象範囲

### 対象

* 発言者と政党の紐づけ
* 政党ごとの発言集約
* 政党別要約
* 共通点・相違点抽出
* 出典付与

### 対象外

* 政党外の会派や無所属区分の詳細管理の高度化
* 政党政策文書との自動比較
* 政党の公式見解の真偽判定

---

## 2.5 機能概要

指定テーマに関する発言を収集し、発言者を政党単位で集約して比較結果を返す。

### 処理フロー

```text
テーマ検索
  ↓
発言取得
  ↓
発言者→政党マッピング
  ↓
政党ごとの発言束ね
  ↓
政党別要約
  ↓
共通点・相違点抽出
  ↓
出典付与
```

---

## 2.6 提供方法

新ツールとして追加する。

### ツール名

* `compare_by_party`

---

## 2.7 compare_by_party ツール仕様

### 入力例

```json
{
  "query": "生成AI",
  "from": "2025-01-01",
  "until": "2025-12-31",
  "nameOfMeeting": "",
  "mode": "standard",
  "include_common_points": true,
  "include_differences": true,
  "max_items": 30
}
```

### 入力項目

* `query`: 対象テーマ
* `from`: 開始日
* `until`: 終了日
* `nameOfMeeting`: 会議名で絞る場合に指定
* `mode`: 出力粒度
* `include_common_points`: 共通点を出すか
* `include_differences`: 相違点を出すか
* `max_items`: 最大対象発言件数

---

## 2.8 出力仕様

### 出力例

```json
{
  "query": "生成AI",
  "overview": "各党とも安全性への懸念には言及しているが、規制強化の強さと活用推進の重みには差が見られた。",
  "party_summaries": [
    {
      "party": "与党",
      "position": "活用推進とルール整備の両立",
      "summary": "産業活用や行政活用を進めつつ、リスク対応を段階的に進める立場。",
      "main_topics": [
        "産業競争力",
        "行政活用",
        "ガイドライン整備"
      ],
      "sources": []
    },
    {
      "party": "野党A",
      "position": "規制強化寄り",
      "summary": "権利侵害や誤情報拡散への懸念を重視し、制度整備をより明確に求める立場。",
      "main_topics": [
        "著作権",
        "誤情報",
        "責任分界"
      ],
      "sources": []
    }
  ],
  "common_points": [
    {
      "point": "安全性確保の必要性",
      "sources": []
    }
  ],
  "differences": [
    {
      "topic": "規制の強さ",
      "description": "与党は活用前提の段階的整備、野党Aはより明示的な規制強化を求めている。",
      "sources": []
    }
  ],
  "conclusion": {
    "text": "各党の共通認識は安全性の確保にあるが、制度化の速度と強度に違いがある。",
    "sources": []
  }
}
```

---

## 2.9 position 候補

政党別の立場表現は以下を基準とする。

* 活用推進
* 慎重
* 規制強化
* 両立志向
* 中立 / 説明中心
* 判定保留

---

## 2.10 処理要件

### 政党マッピング

* 発言者ごとの政党情報を取得または内部辞書で補完する
* 不明な場合は `unknown` または `無所属・不明` として扱う

### 政党別集約

* 政党ごとに発言を束ねる
* 発言量が極端に少ない政党は、必要に応じて注記付きで扱う

### 比較分析

* 各政党の重視論点を抽出
* 共通点を抽出
* 対立点・差異を抽出
* 無理な対立構造を作らない

---

## 2.11 出典付与要件

### 出典対象

* party_summaries
* common_points
* differences
* conclusion

### 出典数

* 政党別要約: 1〜3件
* 共通点: 1〜2件
* 相違点: 1〜3件
* conclusion: 1〜3件

---

## 2.12 モード別仕様

### brief

* 主要政党のみ比較
* 共通点と違いを簡潔に返す

### standard

* 政党別要約
* 共通点
* 相違点
* 結論を返す

### detailed

* 政党別の主張や論点を詳述
* トピック別差異を厚く返す
* 出典数を増やす

---

## 2.13 受入条件

1. 発言が政党別に集約されること
2. 政党ごとの主張要約が返ること
3. 共通点と相違点が区別されること
4. 出典付きで確認できること
5. 不明政党を適切に扱えること

---

# 3. 論点の増減分析機能 仕様書

## 3.1 文書情報

* 機能名: 論点の増減分析機能
* 対象システム: 国会議事録検索・要約MCP
* 版数: 1.0
* 作成日: 2026年4月9日
* 目的: 同一テーマに関する議論の中で、論点の比重の変化を整理できるようにする

---

## 3.2 背景

時系列比較により期間差を把握できても、どの論点が増え、どの論点が減り、何が新たに現れたかを定型的に整理できると、さらに分析価値が高まる。
そのため、本機能では、**期間ごとの論点比重を比較し、増減を分析**する。

---

## 3.3 目的

1. 論点ごとの増加・減少・継続・新規を整理する
2. 議論の重心の変化を可視化する
3. 政策議論の流れを把握しやすくする
4. 出典付きで根拠確認できるようにする

---

## 3.4 対象範囲

### 対象

* 期間別論点抽出
* 論点の対応づけ
* 論点比重の比較
* change_type 判定
* 出典付与

### 対象外

* 厳密な統計分析
* 数理モデルによる重み最適化
* 感情分析
* 外部要因の自動因果推定

---

## 3.5 機能概要

複数期間における同一テーマの発言を収集し、期間ごとの論点を抽出して、その増減を分析する。

### 処理フロー

```text
比較期間指定
  ↓
各期間の発言取得
  ↓
各期間の論点抽出
  ↓
論点対応づけ
  ↓
論点比重比較
  ↓
増加・減少・継続・新規判定
  ↓
出典付与
```

---

## 3.6 提供方法

新ツールとして追加する。

### ツール名

* `analyze_topic_changes`

---

## 3.7 analyze_topic_changes ツール仕様

### 入力例

```json
{
  "query": "生成AI",
  "periods": [
    {
      "label": "2024年",
      "from": "2024-01-01",
      "until": "2024-12-31"
    },
    {
      "label": "2025年",
      "from": "2025-01-01",
      "until": "2025-12-31"
    }
  ],
  "mode": "standard",
  "max_items_per_period": 20,
  "include_emerging_topics": true
}
```

### 入力項目

* `query`: 比較対象テーマ
* `periods`: 比較期間
* `mode`: 出力粒度
* `max_items_per_period`: 各期間の最大対象件数
* `include_emerging_topics`: 新規論点を含めるか

---

## 3.8 出力仕様

### 出力例

```json
{
  "query": "生成AI",
  "overview": "2024年は安全性や規制が中心だったが、2025年は活用や競争力に関する議論が増加した。",
  "topic_changes": [
    {
      "topic": "安全性",
      "change_type": "continued",
      "description": "両期間で継続して主要論点となっている。",
      "sources": {
        "2024年": [],
        "2025年": []
      }
    },
    {
      "topic": "産業活用",
      "change_type": "expanded",
      "description": "2025年に議論比重が大きく増した。",
      "sources": {
        "2024年": [],
        "2025年": []
      }
    },
    {
      "topic": "教育現場での利用",
      "change_type": "new",
      "description": "2025年に新たに目立つ論点として現れた。",
      "sources": {
        "2025年": []
      }
    }
  ],
  "summary_by_period": [
    {
      "label": "2024年",
      "main_topics": ["安全性", "著作権", "規制"],
      "sources": []
    },
    {
      "label": "2025年",
      "main_topics": ["安全性", "産業活用", "行政活用"],
      "sources": []
    }
  ],
  "conclusion": {
    "text": "議論の中心は安全性を維持しつつ、活用と競争力強化へ比重が広がっている。",
    "sources": []
  }
}
```

---

## 3.9 change_type 定義

* `continued`: 継続
* `expanded`: 増加 / 拡大
* `reduced`: 減少
* `new`: 新規
* `shifted`: 同一論点だが扱い方や重心が変化
* `unclear`: 判定困難

---

## 3.10 処理要件

### 期間別論点抽出

* 各期間ごとに主要論点を抽出
* 論点数は2〜5件程度を標準とする

### 論点対応づけ

* 類似名称の論点を統合する
* 表記ゆれを吸収する
* 必要に応じて内部辞書で正規化する

### 比重判定

比重は厳密数値ではなく、以下の複合判断で行う。

* 発言件数
* 発言長
* 重要発言者の登場度
* 要約内での中心性
* LLMによる補助判定

### 増減判定

* 片方の期間にのみ強く現れる場合は `new` または `reduced`
* 両期間で強い場合は `continued`
* 後期間で明らかに比重増なら `expanded`
* 内容が変化した場合は `shifted`

---

## 3.11 出典付与要件

### 出典対象

* 各 topic_changes
* summary_by_period
* conclusion

### 出典数

* topic_changes: 各期間1〜2件
* summary_by_period: 1〜3件
* conclusion: 1〜3件

### 出典情報

* speechID
* issueID
* speaker
* date
* nameOfMeeting
* excerpt

---

## 3.12 モード別仕様

### brief

* 主な増加論点、新規論点、継続論点のみ返す
* 出力軽量化優先

### standard

* topic_changes
* summary_by_period
* conclusion を返す

### detailed

* 各論点の変化理由を厚く返す
* 出典数を増やす
* shifted の説明を詳しく返す

---

## 3.13 受入条件

1. 2期間以上の比較ができること
2. 期間ごとの主要論点が抽出されること
3. 論点に change_type が付与されること
4. 新規・継続・増加・減少が区別されること
5. 出典付きで追跡可能であること

---

# 4. 3機能をまとめて導入する際の共通設計方針

この3機能は、別々に見えて共通土台があります。
まとめて入れるなら、内部では次の共通モジュールを持つときれいです。

## 共通モジュール案

### `topicClassifier.ts`

* 論点抽出
* 論点正規化
* 発言→論点マッピング

### `speakerRoleResolver.ts`

* 発言者属性判定
* 質問者 / 答弁者 / 議員 / 大臣 / 参考人の分類

### `partyResolver.ts`

* 発言者→政党マッピング
* 不明値処理

### `comparisonEngine.ts`

* 政党別比較
* 論点の増減分析
* 差分生成

### `citationMapper.ts`

* 出典ID紐づけ
* excerpt生成
* 出典整形

---

# 5. 導入優先順のおすすめ

3つ同時に仕様化するなら、実装順はこの順が安全です。

1. **質問・答弁ペア要約**
   発言の構造を整理する基礎になる

2. **政党別比較**
   発言者属性の整理を広げる

3. **論点の増減分析**
   期間比較と論点正規化の完成度が必要

この順なら、前の機能で作った土台を次に使えます。
