# 出典付き要約機能 仕様書

## 1. 文書情報

* 機能名: 出典付き要約機能
* 対象システム: 国会議事録検索・要約MCP
* 版数: 1.0
* 目的: 要約結果に対応する原発言（出典）を明示し、信頼性と追跡性を担保する

---

## 2. 背景と目的

従来の要約は、内容が簡潔になる一方で、

* 元発言との対応関係が不明
* 解釈の妥当性が検証できない
* 誤解や過剰解釈のリスクがある

という課題がある。

本機能では、**要約結果の各要素に対して出典（発言）を紐づける**ことで、

* 信頼性向上
* 検証可能性の確保
* 業務利用（報告・資料化）への適用性向上

を実現する。

---

## 3. 機能概要

要約結果の各要素（論点、発言者別要点など）に対して、
対応する元発言の情報を付与する。

出典として付与する情報は以下：

* 発言者
* 会議名
* 開催日
* issueID
* speechID
* 該当発言本文（抜粋）
* 原文参照用URL（任意）

---

## 4. 対象機能

本仕様は以下のMCPツールに適用する。

* summarize_speeches
* summarize_meeting

---

## 5. 出力仕様

## 5.1 全体構造

```json
{
  "summary": {
    "overview": "...",
    "main_points": [
      {
        "point": "...",
        "sources": [ ... ]
      }
    ],
    "speaker_points": [
      {
        "speaker": "...",
        "point": "...",
        "sources": [ ... ]
      }
    ],
    "conclusion": {
      "text": "...",
      "sources": [ ... ]
    }
  }
}
```

---

## 5.2 出典情報構造

```json
{
  "speechID": "abc123",
  "issueID": "xyz789",
  "speaker": "○○議員",
  "date": "2026-02-10",
  "nameOfMeeting": "予算委員会",
  "excerpt": "該当部分の抜粋テキスト（最大300文字）"
}
```

---

## 5.3 出典付与ルール

### ① main_points

* 各論点に対して、**1〜3件の代表発言を紐づける**

### ② speaker_points

* 各発言者の要点に対して、**該当発言を1件以上紐づける**

### ③ conclusion

* 結論の根拠となる発言を**1〜3件紐づける**

---

## 6. 処理フロー

```text
発言取得
  ↓
前処理（除外・結合・重要度判定）
  ↓
チャンク分割
  ↓
部分要約（出典ID付き）
  ↓
統合要約（出典統合）
  ↓
出典情報付与
  ↓
レスポンス生成
```

---

## 7. 出典抽出ロジック

## 7.1 基本方針

LLMに完全依存しない。
**MCP側で出典候補を管理し、LLMは選択・整理のみ行う。**

---

## 7.2 実装方式

### Step 1: 発言にID付与

```text
[ID: S1] ○○議員「・・・」
[ID: S2] △△大臣「・・・」
```

---

### Step 2: LLM入力フォーマット

```text
以下の発言を要約し、各論点ごとに対応する発言IDを指定してください。

発言:
[S1] ...
[S2] ...
[S3] ...
```

---

### Step 3: LLM出力例

```json
{
  "main_points": [
    {
      "point": "生成AIの規制が必要であるとの指摘",
      "source_ids": ["S2", "S5"]
    }
  ]
}
```

---

### Step 4: MCP側で復元

* source_ids → speechIDへマッピング
* excerpt抽出
* 出典情報を構築

---

## 8. 抜粋生成ルール

excerptは以下のルールで生成する。

* 該当発言の一部を切り出す
* 最大300文字
* 可能であれば要点部分を優先
* 文の途中切断は避ける
* 改行・不要空白は整形する

---

## 9. 要約品質制約

LLMに対して以下を強制する。

* 元発言に存在しない内容を追加しない
* 出典と無関係な要約を作らない
* 出典IDを必ず付与する
* 不明な場合は「該当なし」とする

---

## 10. モード別挙動

## 10.1 brief

* 各論点に1件のみ出典
* 出力軽量化優先

## 10.2 standard

* 各論点に1〜2件出典
* バランス重視

## 10.3 detailed

* 各論点に2〜3件出典
* 発言者別にも出典付与
* コスト増

---

## 11. コスト制御

### 11.1 出典候補制限

* LLMに渡す発言数を最大20〜30件に制限

### 11.2 出典数制限

* 1論点あたり最大3件

### 11.3 excerpt制限

* 文字数上限設定（例: 300文字）

---

## 12. エラー処理

### ケース1: 出典紐づけ失敗

* 該当source_idsが存在しない場合
  → 空配列を返却

### ケース2: LLMがIDを返さない

* 再プロンプトまたはfallback処理

### ケース3: 発言不足

* 要約のみ返却、出典は空

---

## 13. 非機能要件

### 13.1 信頼性

* 出典と要約が論理的に一致していること

### 13.2 可読性

* 出典が多すぎて読みにくくならないこと

### 13.3 パフォーマンス

* 出典生成によるレスポンス遅延は許容範囲内

---

## 14. 受入条件

以下を満たすこと。

1. 要約結果に出典が付与されている
2. 出典が実際の発言と一致している
3. 出典から元発言へ追跡可能である
4. 出典数が過剰でない
5. brief / standard / detailed の違いが反映されている

---

# 結論

この仕様のポイントは1つです。

👉 **「LLMに出典を生成させる」のではなく、「IDで紐づけさせる」**
